# 雷诺曼牌局 · 测试版 Demo

一个「大阿尔卡纳 × 雷诺曼」的回合制 1v1 自动战斗 roguelite 原型。
像素牌桌风格，无操作战斗：**你只负责赛前构筑，开打后牌按 CD 自动打出。**

## 运行

直接双击 `index.html` 即可，无需服务器、无需构建、无外部依赖。

调试入口（便于快速看界面）：

| 地址 | 效果 |
|---|---|
| `index.html` | 标题页 |
| `index.html?auto=build` | 直接进入构筑页 |
| `index.html?auto=battle` | 自动配牌并开打 |
| `index.html?auto=result` | 瞬间跑完一场并显示结算页 |

## 已实现的设计

- **40 张雷诺曼**：36 张标准牌 + 37 灵体 / 38 香炉 / 39 床 / 40 市场
- **四类定位**：产（制造命中）/ 续（维持命中）/ 花（消耗连段爆发）/ 吃（连段越高越强）
- **连段 = 命中计数**：每次命中 +1，持续伤害每跳也算；无命中的回合衰减；分档 3 / 5 / 7 / 9 给质变效果
- **敌人 = 原型 × 随机词条**：5 个原型（巨像 / 巫师 / 狼 / 守塔人 / 游魂）× 24 条词条
- **对手立绘**：每个原型有一张 16×16 的像素精灵，战斗页里站在屏幕上方，你在下方
- **随机组合的三条护栏**：
  1. 词条开打前完全可见，允许换牌
  2. 威胁预算：第 1–4 关 1 条（预算 3）、第 5–9 关 2 条（预算 5）、首领 +1
  3. 可解性检查：每条词条在玩家当前牌库里至少有一个解，否则重抽；另有 6 组手工互斥表
- **槽位成长**：初始 3 格 → 3 级 5 格 → 6 级 7 格 → 9 级 9 格
- **9 关推进**：每 3 关一个首领，胜利后升级并随机获得 2 张新牌

## 当前简化与已知问题

这是用来验证「看词条 → 配牌 → 自动打 → 连段分档」这条循环的测试版，不是完整游戏：

1. **大阿尔卡纳武器还没做**。目前只有雷诺曼一侧；武器的正逆位分支尚未接入。
2. **所有数值都是占位**。卡牌效果、敌人血量/攻击、连段阈值都需要重新标定。
3. **连段容易顶满**。当前上限 40，在中后期战斗中大约第 4–5 回合就满了，分档会变成"全员常亮"。需要提高阈值、降低命中频率或加强衰减。
4. **镜影词条做了简化**：原设定是"复制你 CD 最短的牌"，实现为敌人攻击 +30%。
5. **没有存档**，刷新即重开。

## 文件结构

```
index.html          页面骨架（四个 screen）
css/style.css       像素牌桌风格
js/data.js          40 张牌 / 24 条词条 / 5 个原型 / 连段分档 / 数值配置
js/sprites.js       5 个原型的 16×16 像素立绘（纯代码，无图片）
js/engine.js        纯逻辑战斗引擎（无 DOM，可在 Node 里跑）
js/ui.js            界面与流程
tools/simulate.js   无 DOM 的批量战斗模拟器（配平用）
shots/              界面截图
```

## 调参与验证

```bash
node tools/simulate.js
```

会按关卡跑 40 场自动战斗，输出胜率、平均回合数、最高连段，并打印一场完整战斗日志。
当前（笨 AI 配牌）的胜率曲线大致是：前期 100% → 中期 ~50%~70% → 第 9 关 ~55%，
真人针对性配牌应该会明显更高。

主要数值都在 `js/data.js` 的 `CONFIG` 里，改完直接刷新页面即可。

## 设计来源（本轮讨论定下的）

- 雷诺曼没有正逆位，不做翻面；不用扑克花色
- 每张牌的意象 → 一个明确效果 + 冷却 + 时间形状
- 玩家只构筑；战斗自动
- 敌人 = 原型 + 随机词条；词条可见，允许战前换牌
- 难度挂在词条上，不挂在数值上
- DOT 无视免疫：铁壁的正解是毒，而不是更大的数字
